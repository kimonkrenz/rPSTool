# Testing and reproducibility

## Correctness oracle

Upstream PST is the numerical authority. rPSTool tests show that rPSTool calls PST correctly; they do not validate PST against an
independently written algorithm. Two kinds of fidelity are distinguished (see [PST coverage](pst-coverage.md)):

* **Engine fidelity**: values equal what the pinned exported C API computes. Direct-PST fixtures establish this
  and nothing more; a fixture whose arrays, flags or defaults were selected by rPSTool shows engine fidelity and wrapper
  self-consistency only.
* **Application fidelity**: the arrays, flags and defaults selected equal what PST for QGIS selects. This rests on documented
  source traces, on sensitivity tests showing that the selected buffer or flag differs observably from the plausible alternative,
  and on manual comparison in a real QGIS installation ([`tools/validation/qgis-comparison/`](../tools/validation/qgis-comparison/README.md)).
  No comparison in a real QGIS installation has been recorded; intentional differences are listed in
  [QGIS differences](compatibility/qgis-differences.md).

Consistency tests between rPSTool routes (multi-radius against scalar, file against memory, adapter against matrix) are not
evidence of correctness of shared selection logic.

## Test layers

The tests are in `tests/testthat/`.

* **Upstream regression:** transcriptions of the pinned upstream unit tests (static expected constants).
* **Direct PST oracle:** fixtures `tests/testthat/fixtures/*-direct-v3.3.2.R`, generated by the scripts in
  [`tools/reference/`](../tools/reference/README.md) through the official ctypes wrappers against the pinned engine. Each
  fixture records its pinned source blobs. Fixtures use exact hexadecimal numeric literals, because R's decimal parser can
  differ by one ULP across R builds. Installed tests consume only static fixtures; Python and QGIS are not test-time or runtime
  dependencies.
* **R API tests:** argument behaviour, row order, names, classes and missing values.
* **Native boundary and lifecycle tests:** malformed storage, overflow, graph-family mismatch, pointer lifecycle, serialisation,
  exception safety, including a synthetic Arrow C stream producer/consumer for the file-input and result-output boundaries.
* **Platform/build tests:** the `tools/test-*.R` and `tools/verify-*.R` scripts (vendor integrity, build-copy transformations,
  checkout attributes, native build lifecycle), run by `tools/ci/check-local.R`.

Test networks are small but non-degenerate (varying lengths, directions, intersections and angular depths) so that alternative
buffer, flag or default selections give observably different results.

## Floating point

The build uses `-ffp-contract=off` and a fixed set of eight `std::` float overloads
([policy](compatibility/floating-point-policy.md)). Direct fixtures are compared exactly or with the tolerance of the
corresponding upstream test; the only numerical allowance is a one-binary32-ULP tolerance on isovist polygon coordinates.
Bitwise identity across toolchains or parallel execution orders is not assumed beyond what the tests demonstrate.

## Suite modes

The suite contains deliberately exhaustive comparisons with direct PST results. Two modes select how many cases of each fixture
loop run:

| | **Full development mode** | **CRAN mode** (default) |
|---|---|---|
| Selected by | `RPST_FULL_TESTS=true` or `NOT_CRAN=true`; the local gate sets it | neither variable set (an ordinary `R CMD check`) |
| Direct-PST fixture loops | every case | a deterministic subset |
| Skips | none on Linux/macOS; exactly the inventoried tests on Windows | identical |

CRAN mode does not skip the heavy tests. It thins each fixture loop to every n-th case **plus the first case of every level of
every declared stratum** (graph, routine, option signature, weighting, angle threshold, precision, ...) and the first case with
an empty, zero, negative or non-finite argument, so every graph, routine, option set and parameter level is still compared with
the direct PST result. Lifecycle, ownership, failure-path and native-boundary tests and the axial-input graphs are not thinned.
The package gate (`tools/ci/check-package.R`) fails if the full suite runs fewer expectations than
`tools/ci/full-suite-floor.txt`.

```sh
Rscript tools/ci/check-local.R                                    # full development validation (default)
RPST_FULL_TESTS=false Rscript tools/ci/check-package.R ubuntu     # CRAN-mode run (platform: ubuntu | macos | windows)
NOT_CRAN=true Rscript -e 'testthat::test_dir("tests/testthat")'   # full tests from a development checkout
```

The full suite takes much longer than CRAN mode.

## Optional dependencies in tests

`arrow`, `sf`, `jsonlite` and `ggplot2` are suggested packages. The minimum supported `arrow` is 25.0.0, the release the Arrow C declarations in `src/arrow-c-abi` were taken from. Tests and examples that need them skip when they are
absent, except that the local development gate requires them, so a full validation exercises every path. The native Arrow
boundary tests (`test-arrow-native.R`) need no Arrow.

## Windows

Four tests skip on Windows because they depend on POSIX-only facilities (device files, FIFOs, `ulimit -f`); the inventory is
`tools/ci/windows-test-skips.tsv`. On Windows an open Arrow reader blocks replacing or deleting the file, so tests that read
Parquet files through Arrow close their handles explicitly. Build notes are in [build and platforms](build-and-platforms.md).

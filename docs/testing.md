# Testing, reproducibility and supported platforms

## Correctness oracle

Upstream PST is the numerical authority. rPSTool tests prove that rPSTool calls PST correctly; they do not validate it against an
independently rewritten algorithm. Two kinds of authority are distinguished (evidence labels S, N, E, Q as in
[PST coverage](pst-coverage.md)):

* **Engine fidelity** — values equal what the pinned exported C API computes. Direct-PST fixtures (evidence N) establish this
  and nothing more: a fixture whose arrays, flags or defaults were selected by rPSTool proves engine fidelity and wrapper
  self-consistency only.
* **Application fidelity** — the arrays, flags and defaults selected equal what PST for QGIS selects. This rests on documented
  source traces, on sensitivity tests that show the selected buffer or flag differs observably from the plausible alternative,
  and on manual comparison in a real QGIS installation ([`tools/validation/qgis-comparison/`](../tools/validation/qgis-comparison/README.md)).
  No Q-level comparison has been recorded yet; intentional differences are listed in
  [QGIS differences](compatibility/qgis-differences.md).

Consistency tests between rPSTool routes (multi-radius against scalar, file against memory, adapter against matrix) are not
evidence of correctness of shared selection logic.

## Test layers

* **Upstream regression:** transcriptions of the pinned upstream unit tests (static expected constants).
* **Direct PST oracle:** committed fixtures `tests/testthat/fixtures/*-direct-v3.3.2.R`, generated by the development-only
  scripts in [`tools/reference/`](../tools/reference/README.md) through the official ctypes wrappers against the pinned engine.
  Each fixture records its pinned source blobs. Fixtures use exact hexadecimal numeric literals (R's decimal parser can differ by
  one ULP across R builds); `test-fixture-serialization.R` enforces this. Installed tests consume only static fixtures; Python and
  QGIS are never test-time or runtime dependencies.
* **R API tests:** argument behaviour, row order, names, classes and missing values.
* **Native boundary tests:** malformed storage, overflow, graph-family mismatch, pointer lifecycle and exception safety,
  including a synthetic Arrow C stream producer/consumer for the file-input and result-output boundaries.
* **Lifecycle tests:** repeated use, GC, explicit release, dead-pointer rejection, serialisation/deserialisation and output
  lifetime independent of graph and input lifetime.
* **Platform/build tests:** the `tools/test-*.R` and `tools/verify-*.R` scripts (vendor integrity, build-copy transformations,
  mutation rejection, checkout attributes, native build lifecycle) run by `tools/ci/check-local.R`.

Test networks are small but non-degenerate (varying lengths, directions, intersections and angular depths) so that alternative
buffer, flag or default selections give observably different results.

## Floating point

The build uses `-ffp-contract=off` and a fixed set of eight `std::` float overloads
([policy](compatibility/floating-point-policy.md)); `tools/verify-vendor.R` and `tools/test-fp-policy.R` fail closed on drift.
Direct fixtures are compared exactly or with the tolerance of the corresponding upstream test; the only numerical allowance is the
isovist polygon 1-binary32-ULP rule (`expect_isovist_polygon()`, mutation-tested in `test-isovist-ulp-allowance.R`). Bitwise
identity across toolchains or parallel execution orders is not assumed beyond what is demonstrated.

## Suite modes

The suite is dominated by deliberately exhaustive comparisons with direct PST results. Two modes select how many cases of each
fixture loop run:

| | **Full development mode** | **CRAN mode** (default) |
|---|---|---|
| Selected by | `RPST_FULL_TESTS=true` or `NOT_CRAN=true`; the local gate sets it | neither variable set (an ordinary `R CMD check`) |
| Direct-PST fixture loops | every case | a deterministic subset |
| Skips | none on Linux/macOS; exactly the inventoried tests on Windows | identical |

CRAN mode never skips the heavy tests. `tests/testthat/helper-suite-mode.R` provides `rpst_cases()`, which thins a loop to every
n-th case **plus the first case of every level of every declared stratum** (graph, routine, option signature, weighting, angle
threshold, precision, ...) and the first case with an empty, zero, negative or non-finite argument. Every graph, routine, option
set and parameter level is therefore still compared with the direct PST result; only repetitions within a stratum are dropped.
Lifecycle, ownership, failure-path and native-boundary tests are not thinned, and the axial-input graphs are never thinned.
`rpst_thin_items()` thins nested radius items while keeping at least one per radius class.

Guards: `tools/ci/check-package.R` runs the full suite by default and compares the passed expectation count with
`tools/ci/full-suite-floor.txt`, so neither mode can silently run as the other; `tools/ci/check-local.R` always forces full mode for
itself and its subprocesses (`tools/ci/gate-mode.R`); the last test file (`test-zz-suite-mode.R`) asserts from counters that full
mode thinned nothing and CRAN mode thinned something; `test-suite-mode.R` checks the thinning rules on synthetic cases. Lowering the
floor after deliberately removing tests is a reviewed edit.

```sh
Rscript tools/ci/check-local.R                                    # full development validation (default)
RPST_FULL_TESTS=false Rscript tools/ci/check-package.R ubuntu     # CRAN-mode run (platform: ubuntu | macos | windows)
NOT_CRAN=true Rscript -e 'testthat::test_dir("tests/testthat")'   # full tests from a development checkout
```

Reference timings (one Linux sandbox, 4 cores) were about 1500 s for the full suite and about 280 s for CRAN mode; macOS and
Windows timings have not been recorded here.

## Optional dependencies in tests

`arrow` (>= 25.0.0), `sf`, `jsonlite` and `ggplot2` are suggested packages (`classInt` appears only in optional examples). Tests and examples that need them skip cleanly when they are
absent, except that the **local development gate requires them**, so a full validation exercises every path. The native Arrow
boundary tests (`test-arrow-native.R`) need no Arrow at all.

## Windows

Tests that create symbolic links remove them with `rs_remove_entry()` (a native routine): R's `unlink()` cannot remove a
symbolic link on Windows (it sends a junction-only `FSCTL_DELETE_REPARSE_POINT`). Tests that read Parquet files through Arrow close
their handles explicitly (`rs_pq()`, `rs_read_parquet()`), because Arrow's handles block replacing or deleting the file on Windows.

The package builds and every numerical analysis works on Windows, and result-file writing (`output_file`, `spatial_output_file`) is
implemented there (the development suite has passed on Windows; validation of the final release candidate on Windows is still outstanding, see below). The tests that depend on POSIX-only facilities (device
files and FIFOs, `ulimit -f`) call `skip_on_os("windows")`; the exact inventory (4 tests) is
`tools/ci/windows-test-skips.tsv`, re-derived from the test sources and enforced by `tools/ci/test-warning-policy.R`, so a new
Windows-only skip requires a reviewed inventory change.

## Platforms and validation status

Supported targets are macOS (Apple clang), Windows (Rtools) and Linux (GCC or clang). The complete local validation
(`tools/ci/check-local.R`) has passed on macOS Apple Silicon and Windows 11 x64 for earlier states of the package; **the final
release state still needs a clean run on all three platforms** ([release checklist](release-checklist.md)). On Debian-style Linux
toolchains `R CMD check` may report an installed-size NOTE caused by the platform's default `-g` flags ([build and
platforms](build-and-platforms.md)).
